# Границы предварительного MVP и спецификация требований (КТ-1)

> **Проект:** Учебно-тренировочный комплекс «Тренажер оператора энергоблока ВВЭР-1200»  
> **Версия:** MVP-0.1 (Предварительный MVP)  
> **Контрольная точка:** КТ-1 · Стартовый этап проекта  
> **Дата утверждения:** Сентябрь 2026  

---

## 1. Основной сквозной пользовательский сценарий (End-to-End User Flow)

В качестве базового сквозного сценария для проверки жизнеспособности архитектуры выбран регламент:  
**«Инициация аварийного режима (Отключение ГЦН-2 на номинале) → Фиксация защит БЩУ → Парирование аварии оператором»**.

### Пошаговое прохождение сценария:
1. **Инициализация:** Оператор запускает систему. Модель переходит в стационарный режим 100% мощности ($3200$ МВт тепл., $1200$ МВт эл., давление $16.2$ МПа). На мнемосхеме все 4 петли ГЦН подсвечены зеленым, турбина и генератор в сети.
2. **Ввод возмущения:** Инструктор на пульте нажимает кнопку **«Отключение ГЦН-2»**.
3. **Физический отклик:** В математической модели расход во 2-й петле спадает до нуля. Из-за снижения съема тепла температура теплоносителя в петле растет, вызывая срабатывание отрицательного температурного эффекта реактивности.
4. **Сигнализация:** На табло БЩУ загорается желтый транспарант предупредительной защиты **ПЗ-1** и лампа аварии **«ОТКАЗ ГЦН»**.
5. **Действия обучаемого:** Оператор погружает регулирующую группу стержней СУЗ, разгружая реакторную установку до разрешенного уровня мощности на 3 петлях ($\le 67\%$).
6. **Нормализация / Фиксация:** Параметры стабилизируются в новом безопасном коридоре. Событие фиксируется в системном журнале.

## 2. Разделение функционала: Обязательное ядро vs Резерв

Команда строго зафиксировала границы первого выпуска. Перенос функций между ядром и резервом допускается **только через формальное решение (ADR или Change Request)**. «Молчаливый сдвиг границ» запрещен регламентом разработки.

|---|---|:---:|---|
| **1** | **Физическое ядро ОДУ (dt = 0.05 с, 20 Гц)** | 🔴 **Обязательное ядро (Core MVP)** | Фундамент тренажера. Без детерминированного расчета кинетики и термогидравлики система не имеет инженерного смысла. |
| **2** | **WebSocket стриминг телеметрии (20 Гц)** | 🔴 **Обязательное ядро (Core MVP)** | Обеспечивает плавность отображения параметров блочного щита без задержек. |
| **3** | **Интерактивная 2D мнемосхема (Plant Mimic)** | 🔴 **Обязательное ядро (Core MVP)** | Ключевой орган визуализации контуров теплоносителя, положения стержней СУЗ и статусов насосов. |
| **4** | **Светосигнальное табло БЩУ (АЗ-1, ПЗ-1)** | 🔴 **Обязательное ядро (Core MVP)** | Обязательный элемент интерфейса оператора атомной станции. |

| **6** | **Автоматические тесты физики (16 тестов)** | 🔴 **Обязательное ядро (Core MVP)** | Инженерный вердикт соответствия модели техническому регламенту ВВЭР-1200. |
| **7** | *Расчет ксенонового отравления и «йодной ямы»* | 🟡 **Резерв (Backlog КТ-2)** | Требует интеграции уравнений цепочки I-135 $\to$ Xe-135. Будет реализован на этапе КТ-2. |

| **9** | *Многопользовательский режим (несколько пультов)* | 🟡 **Резерв (Backlog КТ-3)** | На этапе КТ-1 сессия проводится в режиме «один инструктор — один пульт». |

## 3. Исходные требования к системе (SRS 0.1)

### 3.1. Функциональные требования:
* **FR-01:** Система должна обеспечивать расчет стационарного номинального режима 100% мощности (3200 МВт тепл. / 1200 МВт эл., $P_1 = 16.2$ МПа, $P_2 = 7.0$ МПа).
* **FR-02:** Сервер симуляции должен рассылать широковещательные пакеты телеметрии с частотой не менее 20 Гц по протоколу WebSocket.
* **FR-03:** Клиентская часть должна отображать технологические параметры на цифровых приборах и на технологической мнемосхеме.
* **FR-04:** Система должна автоматически фиксировать превышение аварийных уставок ($P_1 > 17.8$ МПа) и инициировать гравитационный сброс стержней АЗ-1.

### 3.2. Нефункциональные требования:
* **NFR-01 (Детерминированность):** Результаты симуляции при одинаковых входных воздействиях должны воспроизводиться с точностью до машинного эпсилон.
* **NFR-02 (Производительность):** Задержка доставки телеметрии по локальной сети не должна превышать 15 мс. Нагрузка на центральный процессор клиентского браузера не должна превышать 25%.
* **NFR-03 (Автономность):** Сервер симуляции должен быть способен работать в автономном режиме без подключения UI и проходить все проверочные тесты.
